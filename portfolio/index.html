01 / The person behind the work

I started in code. I stayed for the flow.

I began my career as a developer. I built services and apps at Cognizant for an enterprise client.

Over time, I saw what I enjoyed most. It was not the code. It was the flow.

My developer past still helps. I know what is easy to build. So my designs reach users the way I drew them.

      04 / How I work

      A simple process. Used on every project.

      Understand the user and the rules

      I talk to stakeholders and users. I read the old system when there is one. I list what people need and what the system must do.

      • Stakeholder talks
      • Gap analysis
      • User problem statement

      Define a small first release

      I scope an MVP. I write user stories with clear acceptance criteria. I rank the backlog by user value.

      • MVP scope
      • User stories
      • Priorities

      Design the flow, then the screen

      I map the user flow first. Then I draw wireframes and high-fidelity screens. I use a small set of reusable components.

      • User flows
      • Wireframes
      • Prototypes in Figma

      Check the result against the goal

      I turn business rules into tests. I run user acceptance testing. I compare new behavior with the old and fix every gap.

      • Acceptance criteria
      • UAT
      • Functional parity checks
